## 2026-11-10 — Spring Boot 내장 Tomcat과 실행형 WAR 사용

JSP를 사용할 수 있는 실행형 WAR로 빌드해 별도의 Tomcat 설치 없이 시연한다. jQuery는 WebJar로 포함해 실행 중 외부 CDN에 의존하지 않는다. [Spring Boot JSP 지원 문서](https://docs.spring.io/spring-boot/3.5/reference/web/servlet.html#web.servlet.embedded-container.jsp-limitations)

## 2026-11-10 — 샘플 데이터와 주문 규칙은 서버에서 관리

데이터베이스 설정 없이 주문 흐름을 재현하도록 서버 메모리에 샘플 데이터를 유지한다. 수량과 상태 전이는 서버에서 검증한다. 상태별 건수에는 취소 주문을 포함하고, 주문액 집계에서는 취소를 제외한다.

## 2026-11-16 — 내장 Tomcat 실행형 WAR를 Docker로 배포

Java 21로 빌드하고 Java 21 JRE에서 실행한다. Spring Boot 3.5와 Tomcat 10.1은 Jakarta Servlet 6 계열이므로 별도의 javax 기반 컨테이너로 교체하지 않는다. 컨테이너 안에서는 0.0.0.0에 바인딩하고 호스트에는 loopback 포트만 공개한다. 기존 Caddy에 독립 사이트 파일을 추가해 도메인 루트로 프록시한다.

DB와 업로드가 없는 현재 구현을 유지하므로 영속 볼륨을 추가하지 않는다. 메모리 주문은 재기동 시 초기화된다. 영속화가 필요하면 저장 계층과 전용 볼륨을 함께 구현해야 한다.

## 2026-11-16 — 지원 중인 Spring Boot 4.1로 전환

사용자 요청에 따라 Boot 3.5.16을 4.1.2로, 내장 Tomcat을 10.1.55에서 Boot 관리 버전 11.0.27로 갱신한다. Framework 7.0.10과 Jackson 3.1.7을 함께 사용한다. Java 21과 실행형 WAR를 유지하고 Web MVC starter를 `spring-boot-starter-webmvc`로 교체한다. 애플리케이션 Java·JSP·JS 수정 없이 빌드와 브라우저 호환성을 확인했다.

Docker 이미지와 기존 소스를 백업한 뒤 별도 loopback 후보 컨테이너에서 기동·JSP·API를 확인하고 운영 컨테이너를 교체한다. 운영 healthcheck나 JSP 검사 실패 시 이전 이미지·소스로 되돌리도록 준비했다. Caddy 설정 변경이 필요하지 않은 업데이트다.

## 2026-11-18 — 로컬 화면 개발 모드 추가

`mvn -Pdev spring-boot:run`에서 Maven의 addResources로 JS·CSS 원본을 읽고 JSP는 소스 웹 루트를 사용한다. dev 프로필에서 JSP 변경 검사 간격을 0으로 하고 Tomcat 리소스 캐시 및 정적 파일 캐시를 해제한다. Tomcat 기본 리소스 캐시 때문에 변경 인지가 지연되는 점도 검증해 해제했다. 운영은 검증한 WAR를 Docker 이미지에 포함해 배포한다.


## 2026-11-18 — 데모 주문을 MariaDB에 보관

메모리 저장 결정을 대체한다. Spring JDBC로 조회·등록·상태 변경을 처리하고 Flyway로 스키마와 기준 주문을 관리한다. 공개 데모에서 기준 데이터를 유지하도록 기준 주문의 상태 변경을 막는다. 새 주문의 만료 시각은 DB의 UTC 시간을 기준으로 설정하고, 주문 날짜는 한국 날짜로 기록한다. 등록 시 DB 잠금으로 동시 요청의 공용 등록 한도를 지키며, 상태 변경은 트랜잭션에서 주문을 잠근 후 검증한다. Docker의 전용 볼륨으로 앱 재시작과 저장 데이터의 수명을 분리한다.
