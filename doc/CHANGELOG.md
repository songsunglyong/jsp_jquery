# 변경 이력

## 2026-11-18 — MariaDB 저장과 공개 데모 주문 관리

- 상품·대리점·주문 데이터를 MariaDB에 저장하고 Flyway에서 기준 데이터를 생성하도록 변경했다.
- 공개 데모 등록을 분당 5건, 미만료 주문 1,000건으로 제한했다. 새 주문만 7일 후 만료되며 기준 주문 8건은 조회용으로 유지한다.
- Compose에 외부 공개 포트가 없는 MariaDB와 전용 볼륨을 추가하고 실행 절차를 기록했다.
- 실행형 WAR 빌드와 로컬 MariaDB에서 JSP·jQuery 파일 응답, 입력 검증, 동시 등록 제한, 상태 변경, 앱·DB 재시작 후 보존, 만료 주문 삭제를 확인했다.
- 공개 서버에 MariaDB 11.4.13과 전용 볼륨을 적용했다. 후보에서 앱과 DB를 재시작해 주문과 상태 보존을 확인했고, 공개 HTTPS에서 Chrome으로 JSP와 jQuery AJAX 렌더링을 확인했다. Caddy 및 다른 컨테이너의 상태를 배포 전후 대조했다.

## 2026-11-16

- Spring Boot 4.1.2, Spring Framework 7.0.10, Tomcat 11.0.27, Jackson 3.1.7로 갱신했다. Maven Web MVC starter를 교체하고 Java 21 실행형 WAR 구성을 유지했다.
- 별도 로컬 빌드·Chrome 회귀 검증 및 서버 후보 컨테이너 검증 후 Docker 운영 이미지를 교체했다. 이전 이미지와 소스는 프로젝트 전용 백업에 보관했다.
- 운영 HTTPS에서 JSP·jQuery·검색·주문 등록·출고·완료·취소·네 메뉴·통계와 JSON 날짜·금액·400·409·404 오류 응답을 검증했다. Caddy 메인 및 모든 사이트 설정 체크섬이 일치했다.
- 새 운영 컨테이너 재기동 후 정상 복구와 샘플 주문 8건 초기화를 확인했다. 다른 컨테이너 ID는 모두 일치했고 포트폴리오·JSP 데모는 HTTPS 200이었다. 후보 컨테이너를 정리하고 서버 백업·릴리스 디렉터리를 Docker 빌드 컨텍스트에서 제외했다.
- Tomcat·Spring 보안 공지를 실제 사용 기능과 대조했다. Caddy→앱 HTTP/1.1, HTTP/2 비활성 기본 설정, 미사용 JNDI·WebSocket·SpEL·FreeMarker 등의 조건을 확인했다. HTTP/1.0 프록시 처리 공지는 추가 위험으로 분리했다. Tomcat 패치 30~60분, 지원 중인 Boot 4.x 전환과 배포 검증 2~4시간을 초기 추정으로 기록했다. 실제 마이그레이션 빌드 검증 전 추정이다.
- 배포 컨테이너의 보안 패치 수준을 확인했다. Temurin 21.0.13+9는 현재 Java 21 릴리스와 일치했다. 실제 WAR의 Tomcat 10.1.55, Spring Boot 3.5.16, Framework 6.2.19는 추가 보안 갱신과 지원 버전 전환 검토가 필요해 TODO에 기록했다. 이번 확인에서 런타임이나 의존성 버전을 변경하지 않았다.
- Java 21·Jakarta Servlet 기반 실행형 WAR를 전용 Docker Compose 프로젝트로 배포했다. 컨테이너는 비루트 사용자와 자원 제한·로그 회전·헬스체크를 사용한다.
- 호스트 loopback에만 앱 포트를 연결하고 신규 Caddy 사이트 파일을 root:caddy 0640으로 설치했다. Caddy 사용자로 설정 검증 후 reload했다.
- 일반/DNSSEC 옵션 DNS 응답의 A 레코드 일치, HTTP→HTTPS 전환, 인증서 검증 및 HTTPS 200 응답을 확인했다.
- Chrome에서 JSP·jQuery·주문 AJAX·네 메뉴·통계·새로고침 후 데이터 유지를 검증했다. 컨테이너 재기동 후 메모리 주문이 초기 8건으로 돌아가는 것을 확인했다. DB와 업로드가 없으므로 영속 저장 검사는 해당 사항이 없다.
- 메인 Caddyfile과 기존 portfolio 사이트 체크섬, 기존 포트폴리오 컨테이너 ID를 대조하고 기존 서비스의 localhost·HTTPS 200 응답을 확인했다. 운영 구성과 제한사항은 DEPLOYMENT.md에 기록했다.
